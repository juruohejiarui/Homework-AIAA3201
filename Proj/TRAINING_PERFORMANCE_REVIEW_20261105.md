## 优化

- 单帧输出以 `unsqueeze` 添加 batch 轴，避免不必要的 CPU stack 复制；多帧路径不变。
  Tensor 输出的梯度连接保留，模型表示、帧 ID 和数值不变。
- shell 入口默认 OMP_NUM_THREADS=1，保留用户显式值；冻结 RPC 继承同一线程设置。
- 工作期间公共 YAML 被外部更新为训练路由 .38/.49/.13，本次没有覆盖该配置。
  短探针因此四轮实际都是该路由：每轮排除 16 对热身，测量同一 32 对训练输入，
  耗时 1.2282、1.2239、1.2375、1.2408 秒，中位数约 0.6164 秒/16 对。
  这是输入准备测试，不包含训练反向和完整指标开销，也不是两种路由的有效 A/B。
  预测缓存只读，探针没有训练、写 checkpoint 或生产共享缓存。

## 中断修复

- CPU prefetch 原先使用 ThreadPoolExecutor 的上下文退出和解释器退出 join，
  阻塞读取会阻止训练主进程结束。改用既有 daemon Workers，维持有界、顺序预取；
  关闭时取消排队任务，活跃 CPU 读取不再阻塞进程退出。
- 新 RemotePair 原先先 shutdown(wait=True)，再终止 SSH；当线程正等待远端返回时，
  关闭顺序使其无法被唤醒。现在先取消排队任务并终止本次 SSH，再结束调度器；
  进程回收有界，且关闭后不允许连接线程再创建 SSH。
- live dev 调度器采用相同 Workers，并在清理读取和调度器之前关闭远端和本机 runtime。
- 训练异常先关闭自己的 runtime，再关闭输入迭代器；Ctrl+C 跳过最终制图。
- 不修改正常运行的背压、评分、采样、损失、保存频率或 checkpoint。
  继续使用最近完整 checkpoint 恢复，不承诺保存被中断的优化步。
