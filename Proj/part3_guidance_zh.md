# Part 3：六个方向的训练、工作量与 GPU 资源说明

依据课程项目说明 §5.3 的 A–F 六个方向整理。这里不推荐某一方向，也不替你选择。六个方向是可选路线，课程要求完成有证据的轻量改进、消融和失败分析，不要求全部实现，也没有要求重新训练基础模型。

当前已有模型与部分基准结果；自录视频和 NYUv2 正式评价仍需收尾。以下内容是未来工作说明，不代表 Part 3 已实现。

## 1. 六个方向总表

| 方向 | 要解决什么 | 是否必须训练 | 训练时具体训练什么 | 工作量主要在哪里 | 主要考察内容 |
|---|---|---|---|---|---|
| A 光流引导融合 | 减少帧间闪烁，避免前帧深度错位 | 否 | 可选：预测融合权重或置信度的小网络；基础深度模型和光流模型可冻结 | 光流方向、遮挡剔除、相对尺度、历史传播和场景切换 | 光流对齐误差、静态闪烁、拖影、遮挡恢复、边界及开销 |
| B 米制尺度标定 | 把相对尺度变成有依据的米制尺度，或校正米制预测偏差 | 否 | 可选：从图像/深度特征预测尺度或偏移的小回归头 | 获取独立物理参照、相机内参/坐标定义、稳健拟合和噪声实验 | 米制误差、尺度偏差、参照噪声鲁棒性、跨场景有效性 |
| C 边缘感知优化 | 改善物体边界、薄结构和深度断层 | 否 | 可选：RGB + 原始深度 → 深度残差/边界的小 CNN | 区分纹理边缘与几何边界、保留薄物体、RGB/GT 对齐和损失设计 | 边界 P/R/F1、断层宽度、薄物体表现、全图精度及假边缘 |
| D 不确定性感知平滑 | 只平滑不可靠区域，保留可靠细节 | 否 | 可选：预测误差、置信度或方差的小网络 | 不确定性定义与校准、额外推理、阈值冻结、稳定性与细节折中 | 不确定性是否对应真实误差、稳定性、边界、覆盖率和计算代价 |
| E 高效部署 | 降低时延、显存、存储或功耗 | 否 | 可选：量化感知训练 QAT 或轻量蒸馏；PTQ 标定无需梯度训练 | 导出算子、动态尺寸、后端适配、量化校准及真实设备计时 | 精度–速度–显存折中、模型大小、真实端到端延迟 |
| F 深度感知应用 | 让深度改善一个可量化的下游任务 | 否 | 可选：下游小头；通常可直接用现有模型、ROI 和几何 | 任务定义、真值采集、坐标与单位、交互和应用评价 | 应用正确率/误差、稳定性、误报漏报、延迟 |

“无需训练”仍然需要实现方法、设置参数、正式评价和消融；调参也要使用独立开发数据。使用预训练 RAFT、分割器或检测器进行推理，不等于训练这些模型。

## 2. 工作量与 GPU 压力对照

人日为本项目基线已经能运行、单人熟悉 Python/PyTorch 时的工程估计；不含下载等待、重新录制、基础模型复现及最终论文排版。显存区间是规划量级，**不是实测保证**。

| 方向 | 无训练路线的 GPU 压力 | 增加学习模块后的压力 | 主要时间成本 | 粗略人力工作量 |
|---|---|---|---|---|
| A | Farneback 可在 CPU 上运行，额外 GPU 很少；RAFT 会增加一个光流网络的推理 | 冻结基线、缓存深度后训练小门控，通常按4–12 GiB量级规划；长序列反传显著增加 | 双向光流、遮挡/快速运动实验、拖影定位 | 约3–6人日 |
| B | 尺度拟合主要是 CPU 运算，GPU 由原深度模型决定 | 缓存特征的小回归头通常几 GiB以内；联合微调 Depth Pro 会大幅增加 | 标定参照采集、噪声与跨场景实验 | 约3–6人日 |
| C | 引导滤波/双边滤波可用 CPU 或轻量 GPU | 480×640、小 batch 的浅层残差 CNN，可先按4–12 GiB量级规划；微调编码器更高 | 高质量边界监督、对齐、纹理复制与薄结构分析 | 约4–8人日 |
| D | TTA 串行运行时峰值接近单模型，但 K 次 TTA 约需 K 倍前向计算；并行会加显存 | 小置信头可缓存特征训练；时序联合训练接近 A 的序列成本 | 多次预测、不确定性与误差的关系、阈值和消融 | 约4–8人日 |
| E | 导出和 PTQ 无反向传播；引擎构建可能比实际推理占更多内存 | Small 图像模型 QAT/蒸馏可按12–24 GiB量级起步；视频 QAT 可能需要24–48 GiB或更多 | 算子兼容、动态形状、量化/后端组合、目标设备实测 | 约5–10人日 |
| F | 简单 ROI/几何几乎不增加 GPU；检测/分割模块增加对应推理成本 | 取决于是否训练下游网络；通常无需联合训练深度基础模型 | 有意义的真值、任务流程、异常场景和交互评价 | 约4–10人日 |

以上学习模块量级假设使用混合精度、图像小 batch、冻结基线或缓存输出。选定网络、分辨率、batch 和序列长度后，才能确定具体显存与训练时长。GPU 显存足够不代表训练时间、数据准备或方法有效性已解决。

本机已有实测可作为基线参照：

| 已完成运行 | 精度/输入说明 | 峰值 allocated GPU 显存 |
|---|---|---:|
| DA-V2-S，官方35帧演示 | FP16，源输入640×360 | 约0.33 GiB |
| VDA-S，官方35帧演示 | FP16，源输入640×360，内部时序窗口 | 约2.57 GiB |
| Depth Pro，NYUv2 labeled | FP16，源输入640×480，内部原生多尺度 | 约3.70 GiB |
| VDA-S，KITTI长视频 | FP32，实际短边518 | 约6.94 GiB |

这些是推理数据。训练要额外保留反向激活、梯度与优化器状态，不能据此认定相同网络训练也只需这些显存。48 GiB RTX 4090 D 能为轻量方案提供余量，但不保证任意长度的视频或完整 Depth Pro 联合训练都能放下。

## 3. A：光流引导融合

**实际数据流：**计算相邻 RGB 的前后向光流 → 把上一帧深度投到当前像素位置 → 排除遮挡/越界 → 与当前预测融合 → 更新历史。

- **不训练的实现：**固定融合权重，加前后向光流一致性、RGB/深度变化或边界门控。
- **可训练的实现：**冻结深度模型和光流模型，训练一个小网络决定每个像素采用当前预测还是历史预测。训练输入需要真正连续的 RGB-D，不能把654张独立测试图按文件名串起来。
- **主要工程工作：**warp 方向、遮挡和新出现区域、相对深度表示、场景切换、错误随时间累积，以及可复现的 reset 规则。
- **数据工作：**自录静态、运动和遮挡场景；需要监督训练时，从训练场景 Raw 同步投影得到连续 RGB-D。
- **实验工作：**原始基线、直接 EMA、光流补偿、带遮挡/置信门控的完整方法。比较稳定性，同时观察边界、拖影和遮挡恢复速度。
- **GPU/时间压力：**Farneback 的压力主要在 CPU；RAFT 增加流推理成本。双向流意味着每对帧有两个方向的计算。融合可只保留必要历史帧；若训练时展开长序列，激活显存随序列长度明显增加。
- **必须解释的限制：**移动相机下，同一世界点的 Z 会真实改变；只做像素 warp 不等于完成三维运动补偿。低时序误差也可能来自过度平滑。

## 4. B：米制尺度标定

**实际数据流：**预测深度 → 获取独立的尺度参照 → 求尺度或允许的标定参数 → 输出米制深度 → 对不同场景和噪声做评价。

- **不训练的实现：**已知物体尺寸、相机高度、地面或稀疏测距点配合几何与稳健拟合。
- **可训练的实现：**冻结基础模型，用小回归头估计尺度/偏移，或学习将环境特征映射到标定参数。学习数据中必须有可信尺度监督。
- **主要工程工作：**参照物是否可观测、相机内参、像素对应、异常点剔除、尺度何时更新，以及相对 inverse-depth 的尺度/偏移自由度。
- **数据工作：**采集可复查的尺量、相机高度或稀疏距离；有学习模块时只用训练划分。NYUv2 的相机元数据和米制深度可支持开发。
- **实验工作：**原始米制预测、加入参照的标定、参照点数量/位置变化、参照噪声、跨场景迁移。
- **考察指标：**AbsRel、RMSE、δ1、真实距离 MAE、尺度偏差、噪声增大后的退化。
- **GPU/时间压力：**标定求解通常很轻，工作量主要在人力采集和几何定义；用缓存特征训练小头很轻，联合训练完整米制模型则是另一档成本。
- **必须解释的限制：**使用外部参照后应标明“有标定”；不能用测试 GT 拟合后仍宣称零样本、无参照米制预测。Z 深度、相机到点的距离、两点三维距离要分清。

## 5. C：边缘感知优化

**实际数据流：**RGB 与原始深度 → 提取图像/语义/几何边界 → 保留或修正深度断层 → 输出细化深度。

- **不训练的实现：**引导滤波、联合双边滤波、边界自适应权重或现成分割边界。
- **可训练的实现：**冻结基础模型，训练一个小残差网络，输入 RGB 和基线深度，输出深度修正；可结合深度误差与梯度/边界损失。是否进一步微调基础模型是独立选择。
- **主要工程工作：**RGB 纹理不一定是真实深度边界；还需处理薄物体、天空/透明区域、错误 GT 边界和无效深度。
- **数据工作：**labeled 训练集足以建立小规模实验；更大规模可用预处理训练镜像或训练场景 Raw。需要检查 RGB 与深度是否对应同一投影。
- **实验工作：**基线、仅滤波/仅深度损失、加入 RGB/边界约束；给出局部放大图和跨场景结果。
- **考察指标：**边界 P/R/F1 或有依据的边界误差，以及 AbsRel/RMSE/δ1。要观察是否产生假深度纹理、是否损坏绝对尺度。
- **GPU/时间压力：**冻结基线并缓存预测后，小网络训练显存主要由分辨率、通道数和 batch 决定；语义分割器也有单独成本。工时往往集中在标签与边界评价，而不只是写网络。

## 6. D：不确定性感知平滑

**实际数据流：**估计每个位置的不确定性 → 决定哪里可以平滑、哪里保留当前预测 → 输出置信度和深度。

- **不训练的实现：**TTA 的多次预测分歧、不同模型的分歧、光流或时间一致性作为不确定性代理。
- **可训练的实现：**训练误差/置信度/方差预测头，用 GT 误差监督，或使用适当的概率损失。原始基线可冻结。
- **主要工程工作：**区分真实运动与预测不稳定；让“不确定”与真实错误有关系；控制拒绝像素与覆盖率；在开发集冻结阈值。
- **数据工作：**评价不确定性是否可信需要有 GT 的独立数据；评价真实时序平滑还需要连续片段。单张 labeled 可以开发置信头，不能替代视频评价。
- **实验工作：**无门控平滑、仅不确定性、不同门控来源；同时给出覆盖率与精度/稳定性，不能通过删掉困难像素获得表面提升。
- **考察指标：**误差–不确定性相关性、risk–coverage 或 sparsification 曲线、光流对齐误差、边界和运行代价。分类 ECE 不能未经定义直接当作深度置信指标。
- **GPU/时间压力：**K=4或8的 TTA，前向次数大致变成4或8倍；串行时主要增加时间，并行时还增加激活显存。多个模型常驻会叠加显存，顺序运行可以降低峰值。
- **与 A 的区别：**A 主要研究如何传播和融合历史；D 主要研究哪里可靠、何时应平滑。两者可以组合，但报告要明确改进来自哪一部分。

## 7. E：高效部署

**实际数据流：**固定模型与预处理 → 导出或量化 → 在目标后端运行 → 用相同数据评价精度、速度和显存。

- **不训练的实现：**ONNX/TensorRT 导出、FP16、动态分辨率、PTQ 等。PTQ 需要代表性校准样本，但没有梯度更新。
- **可训练的实现：**QAT 或蒸馏小模型；这会增加训练管线、损失和模型选择工作。
- **主要工程工作：**attention 与自定义算子、动态图与动态尺寸、视频状态、后端支持、前后处理一致性和目标设备实测。
- **数据工作：**校准数据来自训练/开发划分；测试集只做最终比较。要用有代表性的室内、运动和困难场景避免只优化一种输入。
- **实验工作：**原始模型、导出后端、不同精度/分辨率；形成精度–延迟–显存–模型大小的折中表。
- **考察指标：**完整七项深度精度、时序/边界退化、端到端延迟和吞吐量、峰值显存、文件大小；测量时分开首次构建与稳定运行。
- **GPU/时间压力：**导出/PTQ 通常无需长时间梯度训练，但引擎构建和兼容调试可能耗时；QAT/蒸馏才进入训练资源预算。
- **硬件条件：**本机 NVIDIA GPU 可评价对应后端；Core ML 的最终速度与正确性需要 Apple 目标设备，不能用4090的结果替代。

## 8. F：深度感知应用

**实际数据流：**深度预测 → ROI/目标与几何处理 → 应用决策或效果 → 对任务输出进行评价。

- **不训练的实现：**目标距离排序、点击测距、AR 遮挡、可评价的景深效果或碰撞提示；可用手工 ROI 或已发布检测/分割器。
- **可训练的实现：**下游小分类/回归头；如果额外训练目标检测或分割，数据标注与 GPU 成本需单独计算。
- **主要工程工作：**定义任务成功标准、独立真值、交互、时间稳定性、错误处理，以及 RGB/深度/应用输出同时展示。
- **数据工作：**任务自己的独立标签：实际距离或排序、遮挡顺序、提示是否正确等。NYUv2 只提供深度基础，不能自动替代全部应用真值。
- **实验工作：**基线深度驱动的应用与改进后的应用对照，再分距离、运动、材质或光照分析失败情况。
- **考察指标示例：**排序准确率与翻转次数；距离 MAE；遮挡判断准确率；提示 precision/recall、误报率与延迟。
- **GPU/时间压力：**简单几何/ROI 附加成本很小；主要 GPU 开销通常来自基础深度模型和额外检测/分割。主要人力成本在任务标注与可重复采集。
- **必须解释的限制：**相对深度可支持排序，但不能直接称为米制测距；单纯展示漂亮视频不足以证明应用改进。

## 9. 训练数据怎么对应这些方向

| 数据 | 可以支持什么 | 需要保留的边界 |
|---|---|---|
| labeled 的795张训练图 | B/C/D 的小头、小规模监督实验；E 的校准；图像方法开发 | 从训练场景中再划开发验证；654张官方测试图只做最终评价 |
| HF FastDepth 风格47,584张训练图 | 更大规模图像监督、小头/残差网络；深度基础模型缓存 | 是预处理训练子集；保留 H5 浮点深度，不能把有损灰度图当米制 GT |
| 完整 Raw | A/D 的连续 RGB-D、可自行选帧的训练、时序分析 | 需要时间同步、传感器深度转换和投影；训练场景与测试场景分离 |
| KITTI Raw + annotated train | 室外单图米制监督；连续 RGB 支持 A/D 的视频方法；稀疏标注可训练 B/C/D 的模块 | 已有 annotated ZIP 含 train；按 drive 划分，保留当前 val；监督只计算有效深度，不把空洞当0米 |
| Virtual KITTI 2 | 稠密室外深度、连续视频及可选光流/语义真值，支持 A/C/D 的受控监督 | 合成到真实存在域差异；按地点划分，不把同地点天气变体拆到测试集 |
| DIODE | 真实室内外深度，支持 B/C/D 的单图训练与跨域评价 | 有效 mask 必须保留；扫描裁片不是连续视频 |
| ScanNet / TUM RGB-D | 内参、位姿与 RGB-D 序列，支持 A/D 的几何与时序实验 | 时间对应、RGB/深度投影和位姿方向明确；ScanNet 需要授权 |
| 自录片段与独立物理测量 | 真实时序、B 的标定、F 的应用评价 | 无 GT 的视频不编造米制准确率；应用真值需要自己定义和采集 |

训练使用整个 Raw 时，不能把官方测试场景的邻帧混进训练，再以654测试图报告无泄漏泛化。按场景划分，参数选择也只使用训练/开发集。labeled 的654张测试图不能被当作训练图，也不能按文件名串成视频。

训练不限定于 NYUv2。现有 KITTI、NYUv2 可构成室外/室内来源，再按方法需要加入其他数据。新增数据集的体积、监督类型、KITTI train 解压命令及混合训练工作量见 [多数据集训练说明](multi_dataset_training_zh.md)。这些是数据集建议，不是对 A–F 方向的选择建议。

## 10. 共同的交付与资源预算

- 保留原始基线；参数、阈值和 checkpoint 在开发数据上选择后冻结。
- 消融要能回答某个模块是否有效；课程没有规定必须跑旧指南那一长串固定组合。
- 同一评价使用相同输入帧、分辨率、掩码和色标；相对模型说明固定 gauge，米制模型说明单位。
- 主指标没有提高也应报告完整结果、受控对照和失败原因。
- 比较显存时同时记录模型、精度、batch、分辨率和窗口长度；训练与推理分开。
- 训练时长取决于样本数、epoch、batch 和单步耗时。可用“训练步数≈样本数÷batch×epoch”估预算；795张、47,584张和整个 Raw 的开销差异很大。
- CPU 解压、同步投影、硬盘读取和缓存可能成为瓶颈；下载与预处理主要占磁盘/CPU，不消耗基础模型训练显存。
- 最终仍需消融、分类失败案例、效率记录，以及 RGB、depth、应用输出俱全的展示。
